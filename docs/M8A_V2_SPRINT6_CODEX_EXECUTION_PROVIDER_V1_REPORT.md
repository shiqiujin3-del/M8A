## Provider Design

`codex_execution_provider.py` performs:

1. Reads `COTAS_EXECUTION_PACKAGE.md`.
2. Checks local Codex CLI availability.
3. Checks local Codex auth/config presence without printing secrets.
4. Requires explicit environment approval:
   - `M8A_CODEX_EXECUTION_APPROVED=true`
5. If approved, runs:
   - `codex exec`
   - `--sandbox read-only`
   - `--json`
   - `--output-last-message`
6. Forces the prompt to return standard `COTAS_RESULT.json`.
7. Enforces read-only result fields:
   - `modified_files = []`
   - `new_files = []`
8. Calls existing `cotas_result_intake.py`.
9. Optionally triggers existing QA Agent review through Worker Runner.
10. Routes failures to Exception Framework.

## Current Risk Points

1. `codex exec` is a real model execution channel and may transmit task package content to Codex service.
2. `codex exec --sandbox read-only` protects filesystem writes, but it does not by itself prove no model-service communication.
3. A future approved run must keep `modified_files` and `new_files` empty in `COTAS_RESULT.json`.
4. QA approval can only be created after a successful COTAS_RESULT intake and QA task execution.
5. If the user wants strict no-network execution, the next provider should use a local OSS provider instead of Codex service.
