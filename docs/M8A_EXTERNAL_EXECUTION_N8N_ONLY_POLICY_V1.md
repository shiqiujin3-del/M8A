# M8A 外部平台统一 n8n 执行路线政策 V1

日期：2026-07-07
状态：已按 CEO 指令生效

## 一、正式决定

从现在开始，M8A 所有外部平台生产动作统一走 n8n。

正式路线为：

CEO / Commander → AI 员工 → n8n 工作流 → 外部平台 API

不再把零散 Python 脚本、直接 REST API、浏览器手工代操作作为正式生产路线。

## 二、n8n 的定位

n8n 是 M8A 的自动化执行引擎。

它不是 Commander，不是 AI 员工，也不是组织中心。

Commander 负责下达任务，AI 员工负责判断和产出，n8n 负责执行外部平台 API。

## 三、旧路线处理

旧的 WordPress REST/Python 路线保留为只读诊断或备用技术验证。

它不能再作为正式上传路线使用。

原因：历史测试中旧路线没有成功创建线上草稿，曾被 Cloudflare/WAF 拦截。

## 四、权限边界

允许：

1. 通过 n8n 创建草稿。
2. 通过 n8n 读取授权平台数据。
3. 通过 n8n 执行经过 CEO 批准的自动化动作。

不允许：

1. 未经 CEO 批准公开发布。
2. 未经 CEO 批准发送邮件。
3. 未经 CEO 批准删除内容。
4. 未经 CEO 批准修改账号设置。
5. AI 员工读取、复述、记录真实密码、密钥、令牌。

## 五、WordPress 当前状态

WordPress 以后只走 n8n WordPress 节点。

当前 n8n 凭证已保存，但创建草稿实测返回授权失败。

下一步需要重新生成或修正 WordPress Application Password，并确认该用户拥有创建文章/草稿权限。

验证通过前，不允许进入正式发布流程。
